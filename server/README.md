# 지켜로 연구실 서버

Node.js 24 이상, Docker PostgreSQL 17, NAS를 사용하는 서버입니다. 웹과 앱의 로그인·제보·사진/영상/음성·처리 상태·운영 계정·마일리지 교환 신청·오전 11시/오후 7시 알림을 처리합니다. 실행 서버와 프런트엔드는 Supabase SDK 또는 Supabase 주소를 사용하지 않습니다.

## 연구실 컴퓨터에 설치

1. 이전 연결 확인 서버 창에서 Ctrl+C를 눌러 종료합니다. Docker Desktop은 켜 둡니다.
2. 배포 ZIP 안의 파일을 `C:\Users\healt\jikeoro-server`에 덮어씁니다. ZIP에는 기존 `db.env`, `compose.yaml`, `storage.json` 또는 사용자 비밀번호가 포함되어 있지 않습니다. 해당 파일을 유지해야 합니다.
3. `install-server.cmd`를 실행합니다. 패키지를 설치하고, `jikeoro` 스키마를 만들고, 제한된 DB 실행 계정 `jikeoro_api`를 생성합니다. 기존 Docker 볼륨을 지우지 않습니다.
4. 처음 만든 관리자 계정은 **연구실 컴퓨터의** `first-admin.txt`에만 저장됩니다. 이메일과 무작위 비밀번호를 사용합니다. 파일을 공개하거나 GitHub에 올리지 마세요.
5. `start-server.cmd`를 실행합니다.

주소:

- 홈페이지: `http://127.0.0.1:3001/web/`
- 앱: `http://127.0.0.1:3001/app/`
- 운영 로그인: `http://127.0.0.1:3001/web/admin/login/`
- 연결 확인: `http://127.0.0.1:3001/health`

설치는 아직 기존 클라우드 계정·제보·첨부파일을 가져오지 않습니다. 이전 자료를 지우지 말고, 자료 이전과 외부 주소 연결을 마친 뒤 기존 공개 앱·홈페이지를 전환합니다. 초기 관리자와 시험 회원으로 먼저 확인하세요.

구버전의 마일리지 교환 신청 일부는 서버가 아닌 이용자 브라우저에만 저장되어 있습니다. 이전 자료 확인이 끝나기 전에는 브라우저 저장 공간을 초기화하지 마세요. 새 앱은 기존 임시 제보와 교환 신청 기록을 자동 삭제하지 않습니다.

## 저장 위치

DB는 기존 Docker 볼륨 `jikeoro-local_db-data`에서 실행합니다. 파일은 `storage.json`의 `mediaDirectory`에 저장하며, `backupDirectory`는 DB 백업용입니다. NAS를 바꿀 때는 파일을 상대 경로 그대로 복사하고 이 두 설정을 변경한 뒤 기존 파일 조회와 새 업로드를 확인합니다.

원본 파일은 작성자 또는 접근 권한이 있는 운영진만 조회할 수 있습니다. 공개 지도에는 메타데이터를 제거한 최대 280×208 JPEG만 제공합니다. 첨부파일은 한 개당 100MB, 제보당 최대 20개입니다. 앱과 웹 화면의 기존 선택 개수 제한도 적용됩니다. JPEG/PNG/WebP/GIF/AVIF, HEIC/HEIF와 일반 MP4/WebM/음성 형식을 실제 파일 내용으로 확인합니다.

## 외부 접속과 기존 공개 페이지

서버는 `127.0.0.1:3001`에서만 수신합니다. 외부 연결은 Cloudflare Tunnel을 이 주소로 연결합니다. 고정 HTTPS 주소가 생기면 `configure-public.cmd`에서 입력하고 서버를 다시 시작합니다.

기존 GitHub Pages 주소를 유지할 경우 두 저장소의 Actions 변수 `JIKEORO_API_BASE_URL`에 같은 공개 서버 주소를 설정합니다. GitHub 빌드는 각각 기존 경로에서 화면을 제공하고, 데이터 요청은 연구실 서버로 전송합니다. 변수가 비어 있으면 새 화면을 배포하지 않도록 설정합니다. 코드 준비만으로 기존 게시물·설치된 구버전·클라우드 알림 작업이 자동 변경되지는 않습니다.

## 알림

새 서버에서 생성한 VAPID 키는 `push-keys.json`에 저장됩니다. 기존 브라우저 구독 키가 다르면 앱에서 알림을 다시 허용할 때 새 구독으로 교체합니다. 로그인한 기기의 유효한 세션이 있는 경우에만 한국 시간 11시와 19시에 보냅니다. 로그아웃하면 해당 기기 구독이 해제됩니다. 서버가 꺼져 있으면 예약 알림도 실행되지 않습니다. 브라우저/휴대폰에서 실제 수신하는 검증은 HTTPS 주소 연결 후 진행합니다.

## 백업·실행 관리

`backup-db.cmd`는 Docker의 `pg_dump`로 DB를 NAS에 내보내고 SHA-256 파일을 만듭니다. 사진·영상·음성 자체는 NAS의 미디어 폴더에 있습니다. 자동 백업, 재부팅 후 실행 및 NAS 재접속 설정은 운영 전 별도로 확인해야 합니다. Docker Desktop을 사용하는 현재 방식은 재부팅 후 Windows 로그인과 Docker 시작이 필요합니다.

## 개발과 검증

`npm ci`, `npm test`로 API 통합 테스트를 실행합니다. 테스트는 개발 의존성 PGlite의 실제 PostgreSQL SQL 실행기와 임시 저장 폴더를 사용하며, 외부 사용자에게 알림을 보내지 않습니다. 운영에는 PGlite를 설치하지 않고 PostgreSQL 17의 TCP 연결을 사용합니다.

권한 분리, 서버 기준 마일리지, 파일 업로드·원본 접근 차단·사진 미리보기의 EXIF 제거, 잘못된 업로드 정리, 담당 기관별 조회, 예약 알림 중복 방지와 로그아웃, 삭제 후 접근 차단을 검증합니다.

웹·앱 빌드 도구에는 아직 수정판이 없는 picomatch ReDoS 개발 의존성 경고가 남아 있습니다. 신뢰한 소스의 로컬 빌드에만 사용하고 개발 서버는 루프백에만 바인딩합니다. 배포 ZIP에는 Vite나 이 의존성이 포함되지 않으며 실행 의존성 검사에서는 발견된 취약점이 없습니다.

## NAS 제보 CSV 자동 갱신

서버 시작 시 기존 제보 전체를 NAS의 `exports/제보목록.csv`로 내보냅니다. 제보·첨부·처리 상태 등이 저장된 뒤 자동 갱신하고, 1분마다 다시 확인하므로 DB에서 직접 바꾼 내용도 반영합니다. 제보당 한 줄이며 등록 시각 순입니다. 삭제한 제보는 다음 갱신에서 목록에서도 빠집니다.

사용자 ID·이름, 제보 ID, 한국 시간 등록/수정/관찰 시각, 주소·위치 설명·위경도·GPS 오차, 당시 저장된 날씨·기온·날씨 코드, 위험 유형·세부유형·제목·설명·처리 상태·담당 기관·답변, 첨부 개수와 실제 원본/미리보기 경로를 포함합니다. 날씨 정보가 없는 제보는 ‘기록 없음’으로 남기며 새로운 현재 날씨로 과거 기록을 채우지 않습니다. 이메일·비밀번호·세션·알림 키는 내보내지 않습니다.

UTF-8 BOM 형식으로 Excel에서 한글을 읽을 수 있습니다. 이 파일은 DB의 조회용 사본이므로 내용을 직접 편집하면 다음 갱신 때 덮어씁니다. Excel로 열어 잠긴 동안에는 이전 완성본을 유지하고 자동 재시도합니다. 실시간 보기를 위해서는 파일을 닫았다가 다시 여세요.

기본 저장 위치는 `mediaDirectory`의 상위 폴더 안 `exports`이며, `storage.json`의 선택 항목 `exportsDirectory`로 바꿀 수 있습니다. 웹에 공개되는 `public` 폴더 안으로는 지정할 수 없습니다. 웹 공개 다운로드 경로는 추가하지 않습니다. NAS가 연결되지 않았거나 CSV가 잠겨도 제보 접수는 유지하며, 다음 확인 때 다시 만듭니다. 수동 재생성은 서버 폴더의 `export-csv.cmd`를 실행합니다. CSV는 DB 전체 백업을 대체하지 않습니다.

## 영상 촬영 및 100MB 한도

사진·영상·음성 파일은 각각 최대 100,000,000바이트입니다. `/api/media/limits`에서 배포된 서버 한도를 확인할 수 있습니다. 브라우저가 보내는 Blob 원문 한 개가 요청 본문이므로 여러 파일은 각각 따로 전송합니다.

앱·웹의 영상 촬영은 getUserMedia/MediaRecorder를 사용하고 FHD·30fps 이하를 요청합니다. 기본 카메라 앱을 여는 HTML capture 입력은 외부 카메라를 중지할 수 없어 영상 촬영 경로에서 제거했습니다. 녹화 데이터를 주기적으로 확인하고 95MB 부근에서 종료를 요청하여 마지막 인코딩 조각이 들어갈 여유를 남깁니다. 브라우저 지연으로 최종 파일이 100MB를 넘으면 파일을 임의로 잘라 손상시키지 않고 첨부를 거부합니다. 취소·오류·화면 종료 시 카메라와 마이크를 해제합니다. 카메라 API가 없는 기기는 사진첩에서 선택해야 합니다.

100MB 초과 사진첩 파일은 선택 즉시 안내하고 첨부하지 않습니다. 영상 미리보기는 재생 전 전체 데이터를 미리 읽지 않도록 `preload=none`을 적용합니다. 실제 8K 파일의 디코딩 메모리 문제와 업로드 크기 한도는 별개입니다.

## 공개 지도 좋아요와 사진 미리보기

좋아요는 `jikeoro.report_likes`에서 제보 ID·로그인 사용자 ID 조합당 한 건만 저장합니다. 익명 방문자는 합계만 읽고 변경 요청은 서버에서 401로 차단합니다. 좋아요/취소 요청은 원하는 상태를 명시하므로 재시도나 같은 계정의 다른 기기에서 중복 클릭해도 중복 집계되지 않습니다. 사용자 식별자는 공개 집계 응답에 포함하지 않습니다. 제보 삭제 시 연결된 좋아요도 삭제됩니다.

`GET /api/map/reports`는 `likeCount`, `likedByMe`, `hasPhotoPreview`를 반환합니다. `GET /api/map/likes`는 가벼운 합계와 본인 상태만 반환하며 지도는 15초마다, 화면 복귀·로그인 변경 때 갱신합니다. 영상·음성의 `preview_path`가 남아 있어도 실제 `kind=image`인 사진만 지도 미리보기 대상으로 표시합니다.

기존 브라우저의 `jikeoro-map-likes` 값은 사용자 식별과 서버 검증 정보가 없어 새 DB로 가져오지 않습니다. 최초 적용 시 `map-likes-migration.sql`로 표와 실행 계정 권한을 추가해야 합니다. 준비한 NAS 업데이트는 DB 백업과 코드 검증 후 DB 트랜잭션 안에서 적용하며, 기존 파일·CSV·100MB 설정을 보존합니다.
